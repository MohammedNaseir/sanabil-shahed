# مختبرات صقور الكيمياء | منصة سنابل التعليمية

الموقع: **https://sanabil-shahed.naseir.site**

منصة «مختبرات صقور الكيمياء في سنابل» لمنهاج الكيمياء للصف العاشر، إعداد وإشراف أ. شهد نصير.

| المسار | الشاشة |

## مختبر حفظ الكتلة (مختبرات الأسئلة)

مختبر لدرس «قانون حفظ الكتلة» بخمس محطات مختلفة في طريقة اللعب (الكود في `src/labs/mass/`، والنصوص والأسئلة في `data.ts`):

1. **عجلة الصقور:** عجلة بعشرة قطاعات تتوقف عشوائياً على سؤال لم يُحلّ، بمحاولة واحدة لكل سؤال.
2. **بصمة الكيميائي:** تخمين حروف مصطلحين، وكل خطأ يضيف جزءاً من رسم صقر (سبعة أجزاء).
3. **مختبر التحدي:** توصيل ثلاثة مواقف بتفسيراتها (سحب وإفلات، أو اختيار بطاقة ثم موقف).
4. **أكاديمية العلماء:** ورشة معادلات، وميزان أدلة بكفتين، وحساب سريع بمؤقت.
5. **ملعب الصقور:** مباراة كرة قدم بين قسمين، 8 جولات، سؤال مختلف لكل قسم، و5 ثوانٍ للدور.

- **النقاط:** 10 للإجابة الصحيحة، +5 للمحاولة الأولى، +20 مكافأة لكل محطة مكتملة. كل مهمة تُحتسب مرة واحدة (`state.ts`).
- **الحفظ والخادم:** النقاط مهام `ms.<مهمة>` في نظام المهام نفسه (`src/content/massTasks.ts`)؛ تُرسل للخادم وتدخل مجموع الطالب ولوحة الشرف ولوحة المعلمة (عمود «حفظ الكتلة»)، وأعلى مجموع للمختبر 385.
- أهداف المباراة بين القسمين منفصلة عن نقاط الطالب الفردية، وتبقى على الجهاز مع أسماء القسمين.

## مختبر النسب الثابتة (مختبرات الأسئلة)

مختبر لدرس «قانون النسب الثابتة» بخمس محطات (الكود في `src/labs/ratio/`، والنصوص والأسئلة في `data.ts`، والمسار `#/ratio`):

1. **عجلة الصقور:** عشرة أسئلة بلا مؤقت، مع زر تلميح لا يكشف الإجابة وتفسير بعد الاختيار.
2. **من أنا؟:** لوحة محقق: لغزان يُجابان كتابةً (يُطبَّع النص العربي) أو اختيارًا، مع بطاقة المصطلح.
3. **المعلم الصغير:** أربعة أسئلة شرح ومناقشة، والمعلمة هي التي تعرض الإجابة النموذجية وتنتقل.
4. **خزنة الكيمياء:** مسألتان (مع جدول وصور حقيقية للسكروز)؛ الحل يُكشف خطوة خطوة بيد المعلمة، وحل الثانية يفتح الخزنة.
5. **المباراة النهائية:** فريقان، عشرة أسئلة مستقلة تتناوب، و30 ثانية لكل سؤال (المؤقت الوحيد)، مع صافرة وبطاقة حمراء وتصفيق وصندوق كنز.

- **النقاط:** مهام `rt.<مهمة>` في نظام المنصة (`src/content/ratioTasks.ts`): 10 للصحيحة، +5 بلا أخطاء أو تلميح، +20 لكل محطة مكتملة، وأعلى مجموع 370. تدخل لوحة الشرف ولوحة المعلمة، وكل مهمة تُحتسب مرة واحدة.
- **الأصوات** اختيارية ومطفأة افتراضيًا، وفي كل شاشة زر لكتمها/تشغيلها (`src/utils/audio.ts`).
- **صور السكروز** في `public/assets/ratio/` من ويكيميديا كومنز: قصب السكر (Forest & Kim Starr، CC BY 3.0)، والشمندر (USDA، ملكية عامة)، والبطاطا الحلوة (Iyinolamercy، CC0)، وأسماء المصورين تظهر تحت الصور.

## مختبرات المراجعة

- **مختبر الذرة**، ست بوابات حول ذرة دوّارة:
  - رحلة الذرة عبر الزمن
  - فكّر واستنتج
  - فسّر
  - اكتشف الخطأ (لعبة الغرق)
  - ماذا لو؟ (سلسلة التوقعات)
  - التحقيق النهائي (لوحة الأدلة)
- **مختبر العناصر**، فيه الكالسيوم والكبريت والسيليكون:
  - المحطة الأولى في كل عنصر **«عجلة الصقور 🦅»** (`src/content/wheel.ts` و`src/engine/FalconWheel.tsx`): عجلة بخمسة أسئلة خاصة بالعنصر، بنقطتين للإجابة من أول محاولة ونقطة بعد الخطأ. تقدّمها يُحفظ ويُستأنف، وشرح كل سؤال يدخل تقرير الإنجاز ودفتر الباحث.
  - بعدها محطات v5 بترتيبها: محطتا محاكاة: الكالسيوم والماء، التحليل الكهربائي، المجهر الرقمي، منزلق التسخين…
  - وثلاث محطات أسئلة، وتحدّيان سريعان: «صاروخ السرعة» و«التحدي الختامي».
- **11 نوع نشاط:** اختيار، ترتيب، مطابقة، صائد الأخطاء، إكمال، تقرير تحقيق، سباق تتابع، ذاكرة، ربط، بالونات، من أنا.
- **دفتر الباحث** (توقّع، ملاحظة، استنتاج)، والألقاب، وشهادة «رحلة البحث والاكتشاف».
- **لوحة المعلمة:** اعتماد الطلاب، والنقاط لكل مختبر، والإعلانات، وفتح المختبر وإغلاقه.

## التصميم

- **الهوية الخارجية** (الواجهة الرئيسية، اختيار الأقسام، الأقسام، والشريط العلوي): كحلي مع أزرق ملكي وكوبالت ولمسات ذهبية، وخلفية كيميائية حيّة خفيفة (ذرات ومدارات، روابط جزيئية، رموز وجسيمات). الألوان في الصنف `.navy-shell` داخل `src/index.css`، والخلفية في `src/components/home/ChemBackdrop.tsx`.
- **شعار سنابل**: النسخة ذات التفاصيل البيضاء على شارة كحلية (`public/sanabil-logo-white.webp`)، دون تعديل على الشعار نفسه.
- **داخل مختبرَي الذرة والعناصر**: ألوانهما كما هي، مع وضعين داكن وفاتح (زر الشمس/القمر يظهر داخل المختبرات).
- **الخطوط** مدمجة في المشروع (تعمل دون إنترنت): Cairo للعناوين، وTajawal للنصوص.
- **الجوال**: شريط تنقّل سفلي، والنوافذ تنزلق من الأسفل.

## التشغيل محلياً (وضع التطوير)

```bash
npm install
cp .env.example .env.local   # ثم ضعي رمز المعلمة في TEACHER_CODE
npm run dev
```

افتحي `http://localhost:3000`.

> **رمز المعلمة إلزامي.** لا يوجد رمز افتراضي داخل الكود. إذا لم يُضبط `TEACHER_CODE` يعمل المختبر للطلاب بشكل طبيعي، لكن دخول لوحة المعلمة يبقى معطّلاً، وتظهر رسالة توضّح السبب.

### متغيرات البيئة

| المتغير | مطلوب؟ | الوصف |
|---|---|---|
| `TEACHER_CODE` | نعم | رمز دخول لوحة المعلمة |
| `TEACHER_TOKEN_HOURS` | لا | مدة صلاحية جلسة المعلمة بالساعات (الافتراضي 8) |
| `PORT` | لا | منفذ الخادم (الافتراضي 3000) |
| `LAB_DATA_DIR` | لا | مجلد حفظ بيانات الطلاب (الافتراضي `./data`) |
| `TRUST_PROXY` | لا | عدد طبقات البروكسي إن كان الخادم خلف استضافة مثل Cloud Run أو Nginx (مثلاً 1) |

## النشر (وضع الإنتاج)

```bash
npm run build   # يبني الواجهة والخادم
npm start       # يشغّل dist-server/server.js في وضع الإنتاج
```

- شغّلي الأوامر من مجلد المشروع، فالخادم يقرأ `dist/` و `data/` نسبةً إليه.
- بيانات الطلاب تُحفظ في `data/lab-store.json`. **انسخيها احتياطياً** قبل أي تحديث أو نقل.
- جلسات المعلمة محفوظة في ذاكرة الخادم، لذلك تحتاج المعلمة تسجيل الدخول من جديد بعد إعادة تشغيله.

## النشر على Coolify (Docker Compose)

المشروع جاهز للنشر بملفي `Dockerfile` و `docker-compose.yml`.

1. ارفعي المشروع إلى مستودع Git (GitHub أو GitLab أو غيرهما).
2. في Coolify: **New Resource ← Application** واختاري المستودع، ثم **Build Pack: Docker Compose**.
3. في **Environment Variables** أضيفي `TEACHER_CODE` برمز طويل يصعب تخمينه. هذا المتغيّر إلزامي، والنشر يتوقف بدونه.
4. في إعدادات خدمة `app` ضعي الدومين `https://sanabil-shahed.naseir.site`. Coolify يتولى شهادة HTTPS والبروكسي.
5. اضغطي **Deploy**.

**البيانات:** محفوظة في volume اسمه `lab-data` (المسار `/app/data` داخل الحاوية)، ولا تضيع عند إعادة النشر أو التحديث. وفيه مجلد `backups/` بنسخة يومية ونسخة قبل كل «تصفير النقاط» أو حذف طالب (آخر 30 نسخة). يمكنك أيضاً تفعيل النسخ الاحتياطي للـ volume من Coolify.

**التجربة محلياً بنفس الإعداد:**

```bash
docker build -t shhd-labs .
docker run -p 3000:3000 -e TEACHER_CODE=رمز-تجريبي -v shhd-data:/app/data shhd-labs
```

## تسجيل الطلاب

- يسجّل الطالب **اسمه الثلاثي ورقماً سرياً يختاره بنفسه** (4 إلى 6 أرقام، بالأرقام العربية أو اللاتينية). لا يحتاج أي رقم هوية.
- رقم الطالب في المختبر (مثل `SQR-4821`) يولّده الخادم تلقائياً.
- للدخول من جهاز آخر: الاسم نفسه والرقم السري نفسه.
- الرقم السري محفوظ مُجزّأً (hash) لا نصاً، وبعد 5 محاولات خاطئة يُقفل الدخول بذلك الاسم 15 دقيقة.
- إن نسي الطالب رقمه: من لوحة المعلمة ← «الطلاب في المختبر» ← زر المفتاح بجانب اسمه. يظهر رقم جديد مرة واحدة لتعطيه للطالب.
- إغلاق المختبر يمنع التسجيلات الجديدة فقط، والطلاب المسجّلون يستطيعون الدخول.

## كيف تُحفظ النتائج

- كل نتيجة تُحفظ أولاً على جهاز الطالب، ثم تُرسل للخادم عبر طابور يعيد المحاولة تلقائياً إذا انقطع الاتصال. يظهر تحت اسم الطالب في الشريط العلوي: «تم الحفظ» أو «غير متصل» أو «بانتظار اعتماد المعلمة».
- لا يقبل الخادم النقاط قبل أن تعتمد المعلمة الطالب، وتبقى النقاط محفوظة على الجهاز لحين الاعتماد.
- كل نشاط مهمة بمعرّف ثابت، والخادم يقبل المعرّفات المعروفة فقط، وبحد أقصى نقاط كل مهمة. **المحاولة الأولى وحدها تُحتسب**، والإعادة للتدريب دون نقاط، كما في v5.
- المعرّفات:
  - `at.<بوابة>.<نشاط>` لأنشطة الذرة.
  - `<ca|su|si>.<محطة>.<رقم>` لأسئلة محطات العناصر.
  - `<مختبر>.<محطة>.done` علامة إنجاز محطة، ونقاطها صفر.
- عند «تصفير جميع النقاط» من لوحة المعلمة، تُرفض أي نتيجة أقدم من التصفير حتى لو وصلت متأخرة.
- التقدّم ودفتر الباحث محفوظان على الجهاز وعلى الخادم، فيكمل الطالب من حيث توقف حتى لو أغلق الصفحة.
- عند الدخول من جهاز آخر (الاسم والرقم السري نفسهما) ترجع النقاط والدفتر والاستنتاجات. الدفتر يُدمج بين الأجهزة ولا يمسح جهازٌ فارغ ما كُتب على غيره، ولا يراه إلا الطالب نفسه.
- نقاط النسخة القديمة (ألعاب السيليكون والوجهات) تبقى محفوظة في ملف البيانات للرجوع إليها، لكنها لا تدخل في المجموع الجديد.
